# MuleDetector — How to Run

## Prerequisites

### 1. Python Environment

```bash
pip install -r requirements.txt
```

> **GPU:** The model is designed for CUDA-capable GPUs. An RTX 5050 is more than sufficient.
> If no GPU is available, training will fall back to CPU (much slower but functional).

### 2. Required Data Files

You need **two sources** of data:

#### A. Raw CSVs (you download these)

| File | Source | Description |
|------|--------|-------------|
| `HI-Medium_Trans.csv` | [IBM AMLworld on Kaggle](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml) | ~5.7M transactions with timestamps, amounts, bank/account IDs |
| `HI-Medium_accounts.csv` | Same Kaggle dataset | Account metadata: Bank ID, Account Number, Entity ID |

After downloading, update the paths in `config.py`:

```python
# config.py lines 22-26 — update these to your local paths
RAW_TRANSACTIONS_FILE = Path("path/to/HI-Medium_Trans.csv")
RAW_ACCOUNTS_FILE = Path("path/to/HI-Medium_accounts.csv")
```

#### B. Spark Pipeline Parquets (already generated by existing pipeline)

These are the output of `spark_static_pipeline.py` and should already exist:

| File | Features | Used For |
|------|----------|----------|
| `node_account_features.parquet` | 24 columns | Cold-start account memory init |
| `node_bank_features.parquet` | 15 columns | Cold-start bank memory init |
| `node_entity_features.parquet` | 15 columns | Cold-start entity memory init |
| `account_labels.parquet` | account_id, account_label | Training target (binary: mule or not) |
| `edge_account_to_bank.parquet` | account_id, bank_id | Relay edges (Account→Bank) |
| `edge_entity_to_account.parquet` | entity_id, account_id | Relay edges (Entity→Account) |

> **Important:** If these parquets don't exist yet, run `spark_static_pipeline.py` first.
> The output directory is configured in `config.py` as `SPARK_STATIC_DIR`.

## Pipeline Stages

```
Raw CSVs ──→ [Event Replay Pipeline] ──→ events.parquet
                                              │
Spark Parquets ──→ [Stage 1: Chain Tracer] ←──┘
                          │
                    chain_signals.parquet
                          │
Spark Parquets ──→ [Stage 2: TGN + TGAT] ←──── events.parquet
                          │
                    trained model + results
```

### Stage 0 — Event Replay Pipeline

Converts raw CSVs into a chronologically sorted event stream. This is the
primary training input (the Spark parquets provide node features and labels,
not the event stream itself).

```bash
cd c:\Users\Samarth\Desktop\GNN\ml_ly_latest

# Full dataset (~5.7M events)
python -m preprocessing.event_replay_pipeline

# Quick test with a subset
python -m preprocessing.event_replay_pipeline --max-rows 100000
```

**Output:** `data/processed/event_stream/events.parquet`

**What it produces per event:**
- `sender_account_id`, `receiver_account_id` (canonical: `BankID::AccountNumber`)
- `timestamp`, `timestamp_unix`
- `amount_paid`, `amount_received`
- `from_bank`, `to_bank`
- `sender_entity_id`, `receiver_entity_id`
- `payment_currency`, `receiving_currency`, `payment_format`

---

### Stage 1 — Chain Tracer + Conservation Scorer

Runs standalone on the event stream to produce auxiliary chain signals
that Stage 2 uses as a joint-training target.

```bash
python -m stage1.run_stage1
```

**What it does:**
1. **Chain Tracer:** Temporal motif walk starting from known-laundering transactions.
   Follows the money forward in time: if Account A sends to B at time t₁, and B
   sends to C at time t₂ > t₁ within a time window, that's a 2-hop chain.
2. **Random Baseline:** Same algorithm seeded from random (non-laundering) transactions.
   Compares chain-length distributions — laundering chains should be longer.
3. **Conservation Scorer:** For each chain, measures how much money is conserved
   hop-to-hop (tight conservation = likely layering).
4. **Relay Checker:** Analyzes bank/entity clustering to decide whether relay is useful.

**Output:** `data/processed/stage1/chain_signals.parquet` + `stage1_stats.json`

**Options:**
```bash
python -m stage1.run_stage1 --max-gap-hours 48    # tighter time window
python -m stage1.run_stage1 --max-chain-length 10  # longer chains
python -m stage1.run_stage1 --skip-relay-check     # skip bank/entity clustering
```

### Stage 2 — Model Training (TGN + TGAT)

The main model. Processes events chronologically, maintaining per-node
memory vectors for Account, Bank, and Entity nodes.

```bash
python -m stage2.train
```

**How the model works:**
- **Each transaction event** updates exactly **2 account memories** (sender + receiver)
  via a GRU with Time2Vec-encoded elapsed time.
- **Periodically**, Bank/Entity memories are updated via **relay**: aggregate account
  memories through bank/entity hubs using per-relation message computers, then
  broadcast updated bank/entity context back to accounts.
- **TGAT attention** over recent neighbor memories learns which events matter most.
- **Three loss components** (weighted sum):
  1. Primary: Focal loss for mule classification (handles class imbalance)
  2. Conservation: Differentiable flow-conservation regularizer (the novel contribution)
  3. Auxiliary: Chain signal prediction (uses Stage 1 output as training signal)

**Hyperparameters** (all configurable via CLI or `config.py`):
```bash
# Default training
python -m stage2.train

# Custom hyperparameters
python -m stage2.train \
  --num-seeds 5 \
  --num-epochs 30 \
  --lr 0.001 \
  --lambda-conservation 0.1 \
  --lambda-chain-aux 0.3 \
  --focal-gamma 2.0

# Ablation: disable relay
python -m stage2.train --disable-relay

# Ablation: disable conservation loss
python -m stage2.train --lambda-conservation 0

# Ablation: disable chain auxiliary loss
python -m stage2.train --lambda-chain-aux 0
```

**Output:**
- `checkpoints/best_model_seed{N}.pt` — best model per seed
- `results/training_results.json` — per-seed and aggregated metrics

**Metrics reported:** Precision, Recall, F1, AUPRC (not accuracy — meaningless under
severe class imbalance). Variance across ≥3 seeds.

## Troubleshooting

| Problem | Solution |
|---------|----------|
| `FileNotFoundError: Transaction CSV not found` | Update `RAW_TRANSACTIONS_FILE` in `config.py` |
| `FileNotFoundError: node_account_features.parquet` | Run `spark_static_pipeline.py` first |
| `CUDA out of memory` | Reduce `BATCH_SIZE` in `config.py` (default 200) |
| `No positive labels in training set` | Check `account_labels.parquet` — ensure labels are computed |
| `Too few positive/negative labels for stratified split` | Dataset has extreme imbalance — normal, training proceeds with all data |
